# Technical Analysis

The goal of this document is to provide a template and a guide to create good
technical analysis documents.

> Product owner should give context of the functionality to be implemented.
> Questions that can be asked to the product owner until there is enough information to create the technical analysis document

## Content

The technical analysis document should contain the following sections:

- Flows: diagrams that can understand the journey of the user and system
  interactions.
- Use Cases: what the system should provide to the users.
- Current state: specially, if the functionality is already implemented and it
  will be affected by the new implementation.
- Technical Requirements: the specific technical requirements that the system
  must support.
- Non-Functional Requirements: related to performance, security, scalability,
  etc.
- Data Model: the structure of the data and how it is stored and accessed.
- Q&A: a section to answer any questions that may arise during the
  implementation of the project.

## Goal of the document

- Provide a clear and concise description of the technical solution to be
  implemented.
- Break down the work into smaller tasks and assign them to the team
  members.
- Have a clear implementation plan and timeline for the project.
